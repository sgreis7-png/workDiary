# Android APK via TWA — Design

Date: 2026-07-21
Status: approved approach (Option A — TWA wrapper)

## Goal

Installable Android APK for the Agrotop Work Diary, distributed by sideload (file sent to workers), showing the live site fullscreen. Website and APK share all data automatically because both talk to the same Supabase backend — no sync layer is needed or built.

## Approach

Trusted Web Activity (TWA) generated with Bubblewrap CLI, pointing at the production site `https://work-diary-phi.vercel.app`. The APK is a thin shell (~1–2 MB) rendered by the phone's Chrome engine. All app content, updates, offline caching, photos, and web push come from the existing PWA — deploying the website updates the app instantly, with no APK re-release.

Rejected alternatives: Capacitor (native shell, more maintenance, no needed native APIs today) and a native/React Native rewrite (second codebase, unjustified).

## Components

1. **`public/.well-known/assetlinks.json`** — Digital Asset Links file served by the site, containing the SHA-256 fingerprint of the APK signing certificate. This is what removes the browser URL bar in the TWA. Committed to the repo and deployed via the normal Vercel push.
2. **TWA project (`android-twa/` directory, committed to the repo; keystore excluded via `.gitignore`)** — generated by `bubblewrap init` from the live manifest. App identity:
   - Package id: `com.agrotop.workdiary`
   - App name: `יומן עבודה` (short), `Agrotop · יומן עבודה` (full)
   - Icons: existing `pwa-512.png`
   - Display: standalone, portrait, theme `#3aaa35`
3. **Signing keystore** — self-signed key generated locally, stored outside the git repo (and backed up by the user). Sideload does not require Play Store; the same keystore must sign every future APK build, so losing it means workers reinstall.
4. **Output: `app-release.apk`** — the file sent to workers (WhatsApp/link). Install once; content updates arrive from the website.

## Flow

Website deploy (existing) → serves `assetlinks.json` → APK opens site in fullscreen TWA → Supabase auth/session persists inside the TWA's Chrome profile → offline mode and web push work as in the PWA.

## Error handling / constraints

- Phone must have Chrome (or a Chromium browser supporting TWA) installed — standard on Android.
- If `assetlinks.json` is missing or fingerprint mismatches, the app still works but shows a URL bar — verification step below catches this.
- Sideload requires the worker to allow "install from unknown sources" once; include a one-line instruction with the APK.

## Verification

On a real Android phone: install APK → app opens fullscreen with no URL bar → login persists across restarts → airplane-mode shows cached data → push notification arrives.

## Out of scope

Play Store publishing, native APIs, iOS. Can be added later; Play Store would reuse the same TWA project.
